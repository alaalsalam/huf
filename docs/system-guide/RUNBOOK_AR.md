# مرشد النظام — التشغيل والإدارة

الوضع الأول `guide_only`: دليل محلي ومصادر وجولات Frappe أصلية. لا نموذج ولا مفتاح ولا embeddings. فتح الدليل لا يقرأ معاملات الأعمال؛ فحص سجل محفوظ اختيار منفصل مغلق افتراضيًا. وضع `guide_ai` محجوز ومرفوض في هذا الإصدار؛ نقطة التوسعة المستقبلية هي محادثات HUF القائمة، لا محرك محادثة إضافيًا.

## التثبيت

من Bench تجريبية مأذونة، عيّن `SITE` صراحة. لا تستخدم الموقع الافتراضي أو `--site all`.

```bash
bench --site "$SITE" backup --with-files
bench get-app https://github.com/alyf-de/compendium.git --branch version-16
bench get-app https://github.com/alaalsalam/huf.git --branch feature/system-guide
bench --site "$SITE" install-app compendium
HUF_INSTALL_PROFILE=guide_only bench --site "$SITE" install-app huf
bench build --apps huf,compendium
bench --site "$SITE" execute huf.guide.install.prepare
bench --site "$SITE" execute frappe.db.set_single_value --kwargs '{"doctype":"HUF Guide Settings","fieldname":"enabled","value":1}'
bench --site "$SITE" list-apps
```

اختر فرع Compendium وفق **Python الخاص بالـBench** وFrappe، لا Python النظام. فرع `version-16` يتطلب Python 3.14 وFrappe 16. لا تغيّر قيود الحزم بالقوة. إذا كانت الحزم منسوخة ومثبتة مسبقًا فلا تكرر get-app أو install-app. التحديثات التالية تحتاج مزامنة metadata للموقع فقط عند تغير مخططها، وفق نافذة التشغيل المعتمدة؛ لا migrate شاملًا لمجرد تغيير JavaScript.

`HUF_INSTALL_PROFILE=guide_only` مخصص **للتثبيت الجديد**: يحفظ اختيارًا خاصًا بالموقع في HUF Guide Settings، ويتجنب وكلاء وموفّري وكتالوجات HUF التجريبية، ومنح أدواره الافتراضية، وتعديل جدولة الـBench أو حقول تدقيق التطبيقات الأخرى. ويوقف وظائف HUF الاختيارية المجدولة لهذا الموقع وحده؛ لا يمس وظائف التطبيقات الأخرى. لا يغيّر إعدادات HUF القائمة عند تمكين المرشد على تركيب كامل. تبقى حزم HUF الأصلية واعتمادياتها مثبتة حتى إن لم يستعمل المرشد محرك الذكاء الاصطناعي.

راجع الأثر المشترك للبناء وتحميل Python قبل النشر. لا تعِد تشغيل خدمات مواقع أخرى تلقائيًا. إذا بقي عامل الويب على كود قديم، اطلب نافذة تحميل محددة؛ لا تعالج ذلك بتعديل ذاكرة العامل أو تجاوز ضوابطه.

## صفحة الموظف: كيف يستخدم المرشد؟

1. افتح شاشة العمل بصلاحياتك المعتادة، ثم زر **مرشد النظام**. يظهر اسم الشاشة الحالي وثلاثة مداخل: **دليل هذه الشاشة**، **ما الخطوة التالية؟**، **ابحث في دليل الخدمات**.
2. اختر دليل الشاشة أو ابحث بكلمات عربية. تعرض النتائج مقالات Compendium المسموحة فقط. افتح عنوان المقال أو **المصدر** لقراءة الخطوات كاملة.
3. **ما الخطوة التالية؟** يعرض **تعليمات من الدليل** مع عنوان المصدر ورابطه. هذه تعليمات عامة ولا تعني أن طلبك ناقص. يظهر **ابدأ الجولة** فقط لجولة موجودة للشاشة نفسها، و**انتقل إلى الحقل** أو **افتح الصفحة** لوجهة موجودة ومسموحة. لا يغير الانتقال أو الجولة بيانات الطلب.
4. إذا أتاح المسؤول **فحص هذا الطلب**، اضغطه صراحةً لفحص النسخة المحفوظة. تُعرض النتيجة في بطاقة **نتيجة فحص هذا الطلب المحفوظ** منفصلة عن الدليل. لا يرسل فتح اللوحة اسم المستند أو قيمه. المسودة الجديدة أو المعدّلة لا تُفحص؛ احفظها أولًا، ولا ترسل اللوحة قيم المسودة إلى الخادم.
5. الفحص العام `native_required_fields` يعني وجود الحقول الإلزامية المحددة فقط؛ **لا يثبت اكتمال إجراء الأعمال أو اعتماد النشر**. إذا لم توجد تعليمات موثقة للنتيجة، لا يعرض المرشد وجهة مخمّنة. استخدم قناة الدعم المعتمدة، أو اطلب مسؤول الموقع إن لم تُضبط قناة.
6. افتح **فسّر خطأ معروفًا** وأدخل الرمز المستقر فقط، دون تفاصيل أو صور. للخطأ المعروف يظهر السبب الموثق وما تفعله ومصدره. غير المعروف يبقى «لا توجد إرشادات موثقة لهذه الحالة»؛ لا ينشئ المرشد تذكرة أو يرسل بيانات تلقائيًا.
7. عند تغيير الشاشة تُمسح نتائج الشاشة السابقة وتُهمل استجاباتها المتأخرة. Escape يغلق اللوحة ويعيد التركيز إلى زرها. على الهاتف تُفتح اللوحة بعرض الشاشة.

المسار الدائم الأول عام: افتح `/desk/docs/ar/guide/search` وابحث عن **البحث في دليل النظام** ثم المصدر والجولة. لم تُعتمد خدمة أعمال مؤسسة من هذا المثال. اختبارات الحقول المكتملة والناقصة صناعية ومؤقتة؛ لا تُنشر بوصفها سياسة عميل.

## صفحة المسؤول: خدمة ثانية من الإعدادات

افتح **HUF Guide Settings / إعدادات مرشد النظام** من البحث، أو `/desk/huf-guide-settings`. يلزم دور System Manager القائم؛ لا يمنح المرشد أدوارًا جديدة.

1. **التفعيل والظهور:** فعّل المرشد. الأدوار المسموحة الفارغة تعني مستخدمي Desk الحاليين حسب صلاحياتهم؛ الاستثناء له الأولوية. أدخل الشاشات الفعلية سطرًا بسطر مثل `Page:docs` أو `Form:ToDo`، ثم الشاشات المستثناة. هذه سياسة ظهور المرشد، وليست منح صلاحيات بيانات أو بديلًا عن Compendium/Frappe. اختر لغة المستخدم أو العربية/الإنجليزية واللغة البديلة؛ تعطيل البديل يحجب المقال إن غابت لغته المطلوبة.
2. **الدليل والخدمات → المقالات:** أنشئ Compendium Page بعنوان ولغة ومسار ومحتوى وأدوار قراء. اترك Published مغلقًا حتى مراجعة الإجراء. المصدر والنشر والبحث في Compendium وحده. يمكن للتطبيق المالك توزيع Markdown العام وفق آلية Compendium؛ لا تضع معرفة عميل خاصة في Git أو assets.
3. **روابط الخدمات:** أنشئ HUF Guide Binding للشاشة الفعلية، المقال، وتعليمات الخطوة المعتمدة. يمكن تخصيص حقل أو رمز خطأ، والسبب الموثق عند الخطأ. الأعلى أولوية يأتي بعد التطابق الأكثر تحديدًا. لا تنسخ سياسة غير موثقة إلى حقل التعليمات.
4. **الجولات الإرشادية:** أنشئ Form Tour أصليًا للشاشة نفسها، دون حفظ مستند أو شروط تنفيذ أو جولة تالية. اربطه بالخدمة. أضف الوجهة: Page/List/Workspace موجودة، أو حقل مقروء في النموذج الحالي نفسه؛ لا روابط حرة أو معرفات سجلات في الإعدادات. تُراجع صلاحية الوجهة مرة أخرى عند النقر.
5. **الصلاحيات والخصوصية:** اترك فحص السجلات مغلقًا للدليل الثابت. لتفعيله لخدمة: فعّل الخيار العام وخيار الخدمة، وحدّد أدوارًا قائمة وحقولًا داخلية صراحةً. `native_required_fields` يقبل الحقول الإلزامية الأصلية غير المشروطة فقط. حدّد التعليمات الموثقة لنتيجتي الاستيفاء والنقص؛ الفراغ يعطي حالة غير مؤكدة ودعمًا بدل التخمين. أي قاعدة أعمال أخرى تتطلب تسجيل فحص قراءة موثوق من تطبيق المجال، لا Python/SQL/JS في حقل إعداد.
6. **الدعم وفحص الجاهزية:** اضبط تعليمات الاتصال المعتمدة، واحفظ، ثم **فحص جاهزية الخدمات**. يعرض توافق Compendium ونقص المقال المنشور/الجولة/الوجهة/التعليمات وطريقة الإصلاح. رابط كل نتيجة يفتح إعداد خدمتها. نجاح الجاهزية هو سلامة الإعداد لا قبول إجراء الأعمال؛ اختبر بحساب الموظف والحساب المحدود.
7. عطّل المرشد أو فحص السجلات ثم جرّب الطلب المباشر؛ يجب رفضه من الخادم، مع بقاء المقالات والروابط محفوظة. لا تعتمد اختفاء الزر كحماية.

### تجهيز واحد قابل للتكرار

بعد تثبيت التطبيقين المتوافقين على **موقع جديد مأذون** وأخذ نسخة احتياطية:

```bash
bench --site "$SITE" execute huf.guide.install.prepare
```

يتحقق الأمر من وجود التطبيقين وتوافق الإصدار، ثم يزامن **نوعي المرشد فقط**، ويضيف الإعدادات الغائبة والمثال العام دون استبدال قيم محفوظة أو تكرار السجلات. لا يعيد تثبيت التطبيقات، ولا يشغّل migrate شاملًا أو يعيد تشغيل خدمة. يبقى التفعيل اختيار المسؤول؛ الإعداد الموجود يحفظ كما هو. قبل أي كتابة تحقق من مطابقة `$SITE` الفعلية للنطاق. راجع أثر التحميل المشترك واطلب تفويضه عند الحاجة.

### حد فحص المجال للمطور

يسجل تطبيق المجال المثبت `huf_guide_record_checks = {"approved_check": "domain.module.definition"}` في hooks. يعيد المصنع قاموسًا بـ`doctype` و`fields` وقابل استدعاء `run(values)` خالٍ من الكتابة/الشبكة؛ يرجع فقط `{"state": "complete"}` أو `incomplete` أو `unknown`. لا يحمل إعداد الخدمة مسار Python. الحقول المسجلة يجب أن تطابق السماح الصريح، ويُرفض فحص سجل بلا دور وصلاحية مستند وحقل. المستخدم والموقع من جلسة Frappe، لا من المعطيات.

تحتاج حراسة السجل الأصلية إلى تحميل مستند Frappe لتنفيذ hooks النطاق والمالك وUser Permissions كاملة؛ لا يُستبدل بمستند جزئي قد يتجاوز Core. بعد الحراسة لا يصل للفاحص إلا إسقاط الحقول المسموحة، ولا يعود المستند أو قيمه إلى الواجهة. لم يُفعّل فحص مجال خاص في هذا التسليم. لا يستدعي المسار `validate` أو `save` أو `submit` على سجل العمل.

## التحقق

```bash
bench --site "$SITE" execute huf.guide.tests.run.run
```

هذه اختبارات صناعية في معاملة يرجع عنها الاختبار. اختبارات المتصفح في `scripts/guide_browser.cjs` تتطلب `GUIDE_TEST_SITE` و`GUIDE_TEST_BENCH` و`GUIDE_TEST_OUTPUT` وPlaywright/Chromium. تنشئ حسابين مؤقتين غير إداريين ومقالات صناعية، وتزيل بياناتها. وضع `GUIDE_TEST_UX=1` يضيف حساب إعدادات مؤقتًا لاختبار واجهة المسؤول وحالات السجل والجولة والوجهة، ثم يعيد خيار الفحص إلى قيمته الأصلية ويزيل الروابط والجولات والمقالات الخاصة به. استخدم `GUIDE_TEST_SITE_NAME` الصريح لاسم الموقع المتحقق، و`GUIDE_TEST_SITE` لعنوان المتصفح. كلمات المرور مولدة في الذاكرة وتمر إلى أداة الحسابات عبر stdin، ولا تُحفظ. لا تشغّل اختبارات كتابية متزامنة على الموقع نفسه. اختبارات الملكية القديمة لـSkill تحاكي قرارات الترحيل؛ ليست اختبار ترحيل بيانات Legacy حقيقيًا.

قارن مصدر Git المنشور وأصول HTTP والنتائج الفعلية؛ نجاح build أو list-apps وحده لا يثبت اكتمال المسار.

## التعطيل والرجوع

من **HUF Guide Settings** ألغ تفعيل المرشد، أو:

```bash
bench --site "$SITE" execute frappe.db.set_single_value --kwargs '{"doctype":"HUF Guide Settings","fieldname":"enabled","value":0}'
```

يرفض الخادم طلبات المرشد فورًا؛ يختفي الزر عند تحديث الصفحة أو التنقل التالي. لا يحذف ذلك المقالات أو الروابط، ولا يغيّر بقية وظائف تركيب HUF الكامل. لا تحذف تطبيقًا أو تستعد النسخة الاحتياطية تلقائيًا. الرجوع إلى نسخة قبل التثبيت قرار مستقل: احفظ ما استجد من البيانات، وحدد نافذة الخدمات، واستعد قاعدة البيانات والملفات المتطابقة مع نسخة المصدر الموثقة فقط بتفويض منفصل.

## التوافق والمراجع

- Compendium هو مصدر البحث والقراءة الوحيد؛ لا فهرس HUF أو DocType مقالات موازٍ.
- HUF يستعمل override RPC أصليًا من Frappe لحجب عنوان الصفحة من أخطاء رفض Compendium. تبقى قرارات القراءة والنشر لدى Compendium، ومصدره لا يتغير.
- أصبح نوع مهارات HUF هو **HUF Skill** لتجنب `Skill` المملوك لـHRMS. رقعة ما قبل مزامنة المخطط تعيد تسمية القديم فقط إن كان موديوله Huf؛ لا تمس HR ولا تدمج تعريفين غامضين.
- استُفيد من نمط الاستضافة مرة واحدة في Jarvis ومن تأليف Wiki ومراجعة النشر كمراجع فقط، دون نسخ واجهاتهما أو تثبيت Jarvis. مرجع Jarvis تحت AGPL-3.0 وWiki تحت MIT؛ تراخيصهما محفوظة في نسخ المراجع. يحتفظ HUF بترخيصه الأصلي.
