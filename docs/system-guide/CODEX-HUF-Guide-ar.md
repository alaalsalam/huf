# أمر تنفيذ إلى Codex | HUF Guide — مرشد النظام

نفّذ العمل فعليًا: افحص المستودعات والبيئة، أنشئ فرع العمل، طوّر أول ميزة كاملة، ثم ثبّت التطبيقات وفعّل المرشد على الموقع الذي أحدده واختبره. المطلوب تسليم قابل للاستخدام، لا تقرير بحث أو تصميم فقط. لا تربط اسم المنتج أو الفرع أو المسارات أو المحتوى التجريبي بعميل أو مشروع بعينه.

## مدخلات المشغّل

```text
BENCH_PATH = <مسار الـBench أو auto إن أمكن اكتشافه بلا لبس>
TARGET_SITE = <اسم الموقع التجريبي الذي سأحدده>
SERVICE_HINT = <اختياري: الخدمة أو الشاشة التي نبدأ منها>
APP_REPO = https://github.com/alaalsalam/huf.git
WORK_BRANCH = feature/system-guide
MODE = guide_only
```

إن لم أقدّم `TARGET_SITE` أو بقي كعنصر نائب، ابدأ بالفحص والتنزيل والتطوير والاختبارات المعزولة دون تعديل أي موقع أو Bench مشتركة. لا تختر أول موقع ولا الموقع الافتراضي. إن تعذر الوصول للخادم، سلّم الكود وأوامر النشر الدقيقة وصرّح بأن التثبيت لم يتم. لا تطلب مفاتيح نماذج؛ لا تحتاجها هذه الدفعة.

## 1. التوزيع: ماذا تنزّل وماذا تثبّت؟

| المصدر | القرار |
|---|---|
| `alaalsalam/huf` | التطبيق الوحيد الذي نعدّل كوده. أنشئ/استأنف فرع `feature/system-guide` من خط `develop` في الـfork بعد فحص حالته وتسجيل commit البداية. لا تنشئ مستودعًا أو فرعًا لكل موقع. الأصل `tridz-dev/huf` للمقارنة فقط؛ لا تدمج تحديثاته تلقائيًا. |
| `alyf-de/compendium` | نزّل الفرع المتوافق فعليًا مع Frappe وPython، وثبّته كاعتمادية جاهزة لوحدة الدليل على الموقع المستهدف. لا تعدّل مصدره. هو ناشر المقالات ومحرك البحث المحلي، وليس محرك محادثة. |
| Frappe Form Tour | استخدم الموجود في نسخة Framework المثبتة. ليس تطبيقًا إضافيًا. افحص دعم نوع الشاشة والحقول على الموقع قبل ربط الجولة. |
| `aerele/jarvis` و`frappe/wiki` | نزّل نسخ قراءة فقط في مجلد مراجع **خارج** `apps/` ومستودع HUF. من الأول افحص `jarvis/public/js/jarvis_widget.bundle.js` لنمط اللوحة الدائمة. من الثاني افحص تأليف الدليل ومراجعته. لا تثبّتهما ولا تنشئ محرّر Wiki ثانيًا. إن كان Wiki مثبتًا أصلًا فلا تغيّره، ولا تفهرس مساحاته الخاصة تلقائيًا. |

لا تثبّت Ask ALYF أو ERPNext أو Helpdesk أو أي مساعد آخر لأجل المرشد. لا تنسخ أكواد المراجع إلى المنتج دون التحقق من الترخيص والإسناد. احفظ تراخيص الأصل ولا تضع محتوى العميل أو أسراره في Git. إذا غاب فرع متوافق، لا تعدّل قيود الحزم بالقوة ولا ترقِّ Framework لتحل المشكلة.

## 2. عقد المنتج: مفيد قبل الذكاء الاصطناعي

`guide_only` وضع الإصدار الأول: دليل الخدمات والعمليات، بحث محلي بالكلمات، روابط مقالات مرتبطة بالشاشة، جولات تفاعلية، وشرح الأخطاء المعروفة. مربع البحث يعرض **نتائج ومقتطفات وروابط فعلية**؛ لا يعرضها على أنها إجابة ولّدها ذكاء اصطناعي. لا مفاتيح ولا وكيل ولا embeddings ولا قاعدة متجهات ولا اتصال بمزود عند استعمال المرشد. التنزيل وبناء الاعتماديات مرحلة مختلفة عن التشغيل.

`guide_ai` نقطة توسعة، معطلة افتراضيًا لكل موقع. جهّز حدّ التكامل مع محادثات HUF الحالية فقط؛ لا تُنشئ نظام رسائل أو ذاكرة ثانيًا ولا واجهة تدّعي أن المحادثة تعمل. مستقبلًا يُستخدم نموذج محلي يختاره المسؤول من إعدادات HUF، ويُمنع التحويل السحابي في سياسة «محلي فقط». عدم وجود نموذج لا يعطّل الدليل. لا قراءة لمعاملات الأعمال ولا SQL حر ولا أدوات كتابة أو تنفيذ كود في هذه الدفعة. تنطبق هذه السياسة على مسار المرشد، ولا تغيّر إعدادات HUF الموجودة لمستخدمين آخرين.

## 3. المعمارية والبنية المطلوبة

```text
Desk: زر «مرشد النظام» ← لوحة عربية واحدة تبقى أثناء التنقل
                              │
                     Guide API / جلسة Frappe
                       ├─ Knowledge: بحث/قراءة Compendium بهوية المستخدم
                       ├─ Context: ربط الشاشة أو الحقل أو رمز خطأ بمقال/جولة
                       ├─ Tours: تشغيل Form Tour بعد اختيار المستخدم
                       └─ AI: محوّل HUF اختياري؛ لا يستدعى في guide_only
```

بنية مقترحة داخل فرع `huf`؛ طابقها مع نمط المشروع الموجود بدل إنشاء بنية موازية:

```text
huf/guide/                     # api.py, knowledge.py, context.py, policy.py
huf/public/js/guide/           # launcher, panel, route_context؛ bundle بنمط المشروع
huf/<module>/doctype/          # HUF Guide Settings وHUF Guide Binding عند الحاجة
huf/docs/ar/guide/             # دليل المرشد العام فقط، وفق مسار الاكتشاف الفعلي
<domain_app>/docs/ar/…         # معرفة التطبيق الموزّعة معه؛ ليست في نواة HUF
قاعدة الموقع: Compendium Page   # للاستثناءات المحلية المنشورة، وليس مسار ملفات
<existing test layout>/guide/  # اختبارات الخدمة والصلاحيات والواجهة
```

- **Settings:** تفعيل لكل موقع، الوضع، قناة الدعم المعتمدة. الإيقاف يخفي اللوحة ويرفض طلبات API الخاصة بها من الخادم. لا تغيّر بقية وظائف HUF.
- **Binding:** نوع الشاشة أو DocType، وحقل أو حالة أو `error_key` عند الحاجة، ومسار مقال/اسم جولة، والأولوية. النتيجة الأكثر تحديدًا أولًا ثم مقال الشاشة العام. تحقّق من المراجع؛ لا `eval` ولا مسارات ملفات أو روابط حرة تأتي من المتصفح. احترم تقاطع صلاحية الربط مع صلاحية المصدر.
- **العقد البرمجي:** `search_guides(query, context)`، `get_guide(path)`، `resolve_help(context)`؛ هذه أسماء مقترحة لطبقتنا وليست APIs نفترض وجودها. ارجع إلى الفرع الفعلي لـCompendium واستخدم البحث والقراءة اللذين يطبّقان صلاحيات الجلسة، لا قراءة الجداول أو ملفات Markdown مباشرة لتجاوز الصلاحيات. لا فهرس مكرر ولا DocType جديد للمقالات.
- **الواجهة:** استخدم hook مناسبًا لـDesk، ومكوّنًا يُحمَّل مرة واحدة. زر واحد، لوحة جانبية على الحاسوب وكاملة على الهاتف، RTL، دعم لوحة المفاتيح، وعدم تكرار أحداث التنقل. عند تغيّر الشاشة تُحدَّث الاقتراحات وتُهمل الإجابة المتأخرة الخاصة بالشاشة السابقة. لا تظهر للضيف أو صفحة الدخول؛ البوابات المستقلة خارج الدفعة الأولى. لا تشترط ERPNext أو وجود Company.
- **الخصوصية:** هوية المستخدم والموقع من الخادم. مرّر أقل قدر من السياق، مثل نوع الشاشة والحقل، لا قيم النموذج أو المرفقات أو لقطة الشاشة. لا تكشف عنوان مقال محجوب أو مقتطفه أو وجوده في رابط مباشر، وتحقق من النشر والصلاحية عند القراءة أيضًا. لا تتبع خارجيًا ولا تسجيل نصوص حساسة. راجع hooks التثبيت والجدولة؛ لا تفعّل أي مزود أو قناة خارجية كأثر جانبي للمرشد.

## 4. أول تسليم يعمل من البداية للنهاية

اختر خدمة حقيقية واحدة من `SERVICE_HINT` أو من دليل معتمد على الموقع. تحقّق من الحقول والأزرار والحالات المشاهدة. جهّز لها بطاقة خدمة بالعربية (الهدف، المستفيد، المتطلبات، الخطوات، النتيجة، الأعطال المعروفة، الدعم) واربطها بالشاشة والجولة. استخدم أسماء الحقول الداخلية للربط وأسماء الواجهة في الشرح. احفظ المحتوى الخاص كمسودة للمراجعة؛ لا تستنتج سياسات أعمال من الكود ولا تنشرها بوصفها معتمدة. إن لم يوجد محتوى معتمد، استخدم لتجربة مكتملة مقالًا عامًا صحيحًا عن «البحث في دليل النظام»، وجولة على واجهة فعلية تدعم الجولات؛ لا تخترع دورة عمل لدى العميل.

السيناريو: يفتح الموظف الشاشة ← يفتح المرشد ← تظهر الخدمة المناسبة ← يبحث بالعربية أو يقرأ الخطوات ← يفتح المقال أو يبدأ الجولة. للخطأ المعروف اعرض تفسيرًا معتمدًا، ولغير المعروف قل إن السبب غير موثّق واعرض قناة الدعم إن كانت معدّة. لا ترسل تذكرة أو سجلًا أو ملفًا تلقائيًا. اجعل تجهيز البيانات قابلًا للتكرار دون تكرار السجلات أو الكتابة فوق تعديلات الموقع.

## 5. التثبيت المأمون والتحقق

1. اقرأ تعليمات المستودع. افحص الـremotes وحالة Git، وإصدارات Bench/Frappe/Python/Node واعتماديات HUF وCompendium وما هو مثبت على `TARGET_SITE`. سجّل فروع المصدر وSHA. لا `force push` ولا حذف أو إخفاء تغييرات المستخدم. لا تعدّل `develop`، ولا ترفع إلى upstream. ادفع فرع العمل إلى الـfork إن كانت صلاحية الدفع متاحة؛ وإلا احتفظ بالـcommit محليًا وأعطني أمر الدفع.
2. التطوير والبناء على Bench تجريبية معزولة. `get-app` وتبديل فرع مستودع في `apps/` وبناء الأصول قد تؤثر في مواقع Bench أخرى. إذا اتضح أن الـBench مشتركة مع الإنتاج أو لم يكن مسموحًا تعديلها، لا تبدّل فرع التطبيق فيها؛ أكمل على نسخة معزولة، واترك النشر الإنتاجي لموافقة منفصلة. إذا حُدد موقع تجريبي مأذون ومعزول فنفّذ التثبيت فعلًا بعد فحص المساحة وأخذ نسخة قاعدة وملفات والتحقق من وجودها. لا تستخدم `--site all` أو `bench update` أو `reinstall` أو `--force`.
3. ثبّت `compendium` ثم `huf` على الموقع المحدد فقط إن لم يكونا مثبتين، وابنِ الأصول ونفّذ ترحيل الموقع إذا لزم. لا تعِد التثبيت فوق نسخة قائمة. فعّل Guide لهذا الموقع وحده في `guide_only` واترك المواقع الأخرى كما هي. تحقّق بأمر `bench --site <TARGET_SITE> list-apps` **وبفتح المرشد بحساب موظف غير إداري**؛ وجود التطبيق في `apps/` لا يكفي.
4. اختبر: تشغيل بلا مفتاح وبلا اتصال صادر وقت الاستخدام؛ البحث العربي ورابط المصدر والجولة؛ مستخدمين بصلاحيتين مختلفتين؛ سحب صلاحية/إلغاء نشر؛ منع الوصول المباشر لمقال محجوب؛ عدم تكرار الزر بعد التنقل؛ RTL والهاتف؛ خطأ غير معروف؛ تعطيل المرشد؛ وعدم اختلاط المواقع. استخدم مواقع وبيانات اصطناعية معزولة لاختبارات العزل، ولا تختبر على بيانات عميل حقيقية بلا تفويض. سجّل ما لم يمكن إثباته بدل تصويره كنجاح.
5. سلّم ملخصًا عربيًا: الفرع وSHA، التطبيقات المنزّلة مقابل المثبّتة، الموقع والوضع، طريقة فتح المرشد، إضافة خدمة/مقال/جولة بلا تعديل النواة، نتائج الاختبارات، والقيود. اكتب runbook قصيرًا يتضمن أوامر قابلة للإعادة وتعطيل الميزة وخطة الرجوع المناسبة للنسخة الاحتياطية. لا تستعد النسخة الاحتياطية ولا تحذف أي تطبيق تلقائيًا.

تعريف الإنجاز: يستطيع موظف غير إداري العثور على الإجراء العربي الصحيح من شاشته وبدء الإرشاد دون نموذج، دون كشف محتوى محجوب ودون كود خاص باسم العميل. نفّذ هذه الدفعة قبل أي عمل على التدريب أو الاستعلامات الحية أو الأتمتة.
