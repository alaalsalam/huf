# مهمة Codex: تجهيز تجربة «مرشد النظام» وإعداداته على Development

نفّذ التحسينات واختبرها، ولا تكتفِ بخطة أو تصميم. ابنِ على التنفيذ الموجود، وحافظ على ما يعمل. هذه المواصفة تحلّ محل أي تعليمات سابقة تطلب إزالة Compendium أو إنشاء نظام مقالات داخل HUF.

## 1. القرار والنطاق

- مستودع التطوير: `https://github.com/alaalsalam/huf.git`. فرع العمل الوحيد: `feature/system-guide`. استخدم `bc2a01da` مرجعًا للتنفيذ السابق، لا هدفًا لإرجاع الفرع إليه. افحص آخر commit وحالة الملفات قبل التعديل، ولا تمسح عملًا قائمًا.
- الهدف هو موقع Development الذي ظهر سابقًا على `dev.mwe-mis.maward.org`. تحقّق من اسم Frappe Site الفعلي المطابق له قبل أي عملية كتابة. لا تفترض أن اسم مجلد الموقع هو اسم النطاق، ولا تستخدم الموقع الافتراضي أو `--site all`. لا تربط كود المنتج أو محتوى الدليل بهذا النطاق أو باسم مشروع بعينه.
- نعتمد **HUF وCompendium**: التطوير والواجهة والسياسات في HUF، والمقالات والنشر والبحث في Compendium، والجولات من Frappe Framework. لا تعدّل نواة Compendium، ولا تضف تطبيقًا أو محرر مقالات أو فهرس بحث موازيًا. لا تغيّر Wiki أو Jarvis أو AMS أو مستودع الذاكرة.
- نفّذ أولًا جردًا مختصرًا للوحة الحالية و`HUF Guide Settings` و`HUF Guide Binding` و`huf/guide` وأصول Desk والاختبارات ودليل التشغيل. عدّل الموجود بدل إنشاء واجهة أو API ثانية. النمط التشغيلي لهذا التسليم هو `guide_only`: **لا نموذج، لا وكيل، لا API key، لا embeddings ولا إرسال إلى مزود خارجي**.

## 2. ما يراه الموظف

1. أبقِ نقطة دخول واحدة باسم **«مرشد النظام»** في صفحات Desk المصرّح بها. افتح لوحة جانبية على الحاسوب وعرضًا ملائمًا على الهاتف. احترم RTL ولغة المستخدم، واجعل التنقل بلوحة المفاتيح والإغلاق بـEscape وإعادة التركيز للزر تعمل. لا تكرر الزر عند تغيير المسار ولا تحجب أزرار الحفظ والاعتماد.
2. عند الفتح، اعرض اسم الشاشة الحالي وثلاثة مداخل واضحة: **«دليل هذه الشاشة»**، **«ما الخطوة التالية؟»**، **«ابحث في دليل الخدمات»**. اعرض «ابدأ الجولة» و«انتقل إلى الحقل/الصفحة» داخل النتيجة فقط عندما تكون الوجهة موجودة ومسموحة. استخدم البحث والمقالات الحقيقية؛ لا تعرض واجهة توهم الموظف بأنه يتحدث إلى نموذج في `guide_only`.
3. أظهر عنوان المصدر ورابطه مع كل تعليمات موثقة. ميّز بوضوح بين «من الدليل» و«فحص لهذا الطلب» و«فحص مبدئي لمسودة غير محفوظة». عند تغيير الشاشة، حدّث السياق وتجاهل أي استجابة متأخرة تخص الشاشة السابقة. صمّم حالات مفهومة للتحميل، وعدم وجود دليل، وفشل الاتصال، وانعدام النتائج، مع بديل عملي بدل لوحة فارغة. لا تكشف وجود مقال محجوب.
4. عند خطأ معروف، اعرض **السبب المؤكد ← ما يفعله المستخدم ← رابط التصحيح أو المصدر**. وعندما لا يعرف النظام السبب، قل «لا توجد إرشادات موثقة لهذه الحالة» وأظهر قناة الدعم التي حددها المسؤول. لا تسجل الشاشة ولا ترسل تذكرة أو تفاصيل موظف تلقائيًا.

## 3. ميزة «ما الخطوة التالية؟»

نفّذ مسارًا واحدًا كاملًا لخدمة أعمال موجودة فعلًا على الموقع التجريبي. اخترها من الإجراءات الموثقة والمأذون باستخدامها، لا من تخمين أسماء الحقول أو سياسات الاعتماد. أعد استخدام `HUF Guide Binding` والـWorkflow والتحققات الموجودة في تطبيق الخدمة. أضف نقطة توسعة صغيرة فقط عند الحاجة، دون تعديل منطق العمل أو إنشاء محرك قواعد عام.

- **افتراضيًا: دليل فقط.** يكفي نوع الشاشة واسمها والحقل أو رمز الخطأ لعرض التعليمات العامة. لا تطلب اسم مستند أو محتواه عند إغلاق فحص السجل.
- **اختياريًا وبطلب الموظف: فحص السجل الحالي.** يفعّله المسؤول لخدمة محددة. استخرج المستخدم والموقع من جلسة الخادم، وأعد التحقق من الشركة/نطاق المشروع وصلاحيات المستند والحقول. اقرأ أقل بيانات لازمة، وأعد سببًا موثقًا وخطوة تالية ووجهة مسموحة، لا المستند كاملًا. لا تجعل نتيجة مشتقة تسرّب قيمة أو حقلًا محميًا.
- استخدم فحوص قراءة خالية من الآثار الجانبية. لا تستدعِ `save` أو `submit` أو تحققًا قد ينشئ بيانات، ولا تنفّذ Python أو SQL أو JavaScript من حقل إعداد. لا تعتبر قيَم المسودة في المتصفح حقيقة محفوظة. لا تعرض خطوة لا يستطيع المستخدم تنفيذها؛ أعطه بديلًا مسموحًا عند وجوده.
- مثال لشكل النتيجة، لا قاعدة مقترحة للموقع: «المرفق المطلوب غير موجود» + «انتقل إلى حقل المرفق» + «اقرأ إجراء الإرسال». إذا لم تتوفر خدمة ذات إجراء معتمد، أنجز الميزة واختبرها ببيانات اصطناعية معزولة، وسجّل أن قبول خدمة حقيقية لم يُختبر. لا تنشر إجراء أعمال مختلقًا.

## 4. إعدادات مسؤول الموقع

وسّع **HUF Guide Settings** نفسها، مع روابط مباشرة إلى قوائم المقالات والروابط والجولات المصرح بها. لا تنشئ شاشات متكررة. نظّم الإعدادات في أربع مجموعات:

| المجموعة | المطلوب |
|---|---|
| التفعيل والظهور | تشغيل/تعطيل لكل موقع، من يرى المرشد، الشاشات المشمولة والمستثناة، واللغة الافتراضية والرجوع عند غياب الترجمة. الاستثناء والمنع لهما الأولوية. |
| الدليل والخدمات | عرض مصدر المقالات وحالته، وضبط روابط الشاشة/الخدمة/الحقل/رمز الخطأ بالمقال والجولة والوجهة التالية. اجعل إضافة خدمة ثانية ذات إرشاد ثابت ممكنة من الإعدادات بلا تعديل كود. أي فحص ديناميكي جديد يُضاف في تطبيق المجال، لا كسكربت حر. |
| الصلاحيات والخصوصية | الدليل والبحث المحلي متاحان حسب الصلاحية؛ فحص المستندات **مغلق افتراضيًا** ويُفتح لكل خدمة ودور وحقول محددة. تعطيل الميزة يمنع استدعاءها من API أيضًا. لا تمنح أدوارًا جديدة تلقائيًا. |
| الدعم وفحص الجاهزية | قناة الدعم المعتمدة، وفحص للمدير يوضح: هل Compendium مثبت ومتوافق؟ هل يوجد مقال منشور؟ هل ربط الشاشة والجولة والوجهة صالح؟ اعرض المشكلة وخطوة إصلاحها، لا مجرد علامة خضراء. |

لا تستبدل إعدادات موقع قائم بقيم افتراضية عند الترقية. لا تعرض مفاتيح مزودين أو إعدادات ذكاء غير عاملة في هذه النسخة. اجعل تعطيل المرشد قابلًا للعكس دون حذف المحتوى.

## 5. التفعيل والتسليم

- على Development المصرح به: خذ نسخة احتياطية قبل تغييرات المخطط والبيانات، وثبّت ما ينقص فقط بعد التحقق من توافق الفرع والـBench. لا تعد تثبيت HUF أو Compendium إن كانا موجودين. اجعل تجهيز الإعدادات والروابط قابلًا للتكرار دون مضاعفة السجلات. لا تبدّل فرعًا في Bench مشتركة ولا تعِد تشغيل عمال مشتركين بلا تفويض صريح لهذه العملية.
- شغّل اختبارات المرشد السابقة، وأضف اختبارات للميزة. اختبر في المتصفح بحساب موظف غير إداري: فتح اللوحة والبحث بالعربية، المصدر والجولة، الانتقال إلى حقل/صفحة، تغيير المسار بسرعة، الهاتف وRTL، وحالات الخدمة المكتملة والناقصة وغير المعروفة. اختبر الرفض عبر API لمستخدم محدود، وألا يتسرب عنوان أو مقتطف بعد سحب الدور أو إلغاء النشر. أثبت أن الدليل لا يستدعي مزود AI، وأن تعطيل فحص السجل يمنع قراءة المعاملة فعلًا. اختبر عزل موقعين بأسماء مسارات متطابقة متى توفرت بيئة مأذونة؛ وإلا سجّل أنه غير مختبر.
- حدّث `docs/system-guide/RUNBOOK_AR.md` بصفحتين عمليتين: «كيف يستخدم الموظف المرشد؟» و«كيف يجهّز المسؤول خدمة ثانية ويختبرها ويعطّلها؟». وثّق أيضًا أمر تجهيز واحدًا قابلًا للتكرار لموقع جديد مع فحص مسبق؛ لا تفترض أن كل المواقع تستخدم الإصدار نفسه.
- ارفع التغييرات إلى `feature/system-guide` فقط عند توفر صلاحية الدفع؛ لا تدمج في `develop`. سلّم: الـcommit، ما فُعّل فعلًا وعلى أي موقع، أين يفتح الموظف اللوحة وأين يفتح المسؤول الإعدادات، الخدمة المختبرة، نتائج الاختبارات، وما بقي غير مختبر. لا تعتبر نجاح البناء وحده نجاحًا لتجربة الموظف.

**معيار الإنجاز:** يدخل موظف عادي شاشة خدمة، ويفهم ما عليه فعله، ويصل إلى المصدر والحقل أو الصفحة الصحيحة من داخل المرشد، دون نموذج ذكاء ودون رؤية ما لا يحق له. ويستطيع مسؤول الموقع تهيئة دليل خدمة ثانية وربطها دون استدعاء مطوّر.
